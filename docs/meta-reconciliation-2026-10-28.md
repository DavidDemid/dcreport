Проверка: 1032 − 304 − 23 − 1 + 28 = 732. В 304 входят 303 непустых отсутствующих ID и одна строка без ID.
Последние 28 состоят из 25 других FB ID и трёх CRM-записей Meta Ads без FB ID.

728 ID соответствуют 738 CRM-карточкам, а не 738 уникальным заявкам. Один ID из Facebook-списка
связан с 11 разными CRM-карточками и разными контактами. Такое совпадение неоднозначно;
строго однозначных ID-сопоставлений 727. Эти данные нельзя автоматически считать дублями людей.

## Дополнительные контакты

Контактная сверка не использует имена. Для всех 304 строк без прямого ID-совпадения:
51 строка имеет единственного октябрьского кандидата по нормализованному email и/или телефону,
одна — двух кандидатов, 252 — не имеют октябрьского кандидата.
Одна из последних 252 имеет контактное совпадение только вне октября.

После исключения неоднозначностей, повторного использования контактов и кандидатов с другим
FB ID остаётся 41 взаимно однозначный кандидат без рекламных метаданных: 31 chat, 8 Unknown,
2 уже Meta Ads. Это совпадения контактов, не доказательство той же рекламной заявки.
Автоматическая переклассификация только по контактам недопустима.

## Ограничения

- В Facebook-файле все ячейки даты создания и исходного времени отправки пустые, включая XML-значения. Формул с невыполненным пересчётом нет. Период указан только в заголовке.
- CRM-выгрузка не содержит закрытых won/lost этапов. Нельзя доказать, что отсутствующие в файле заявки отсутствуют в самой CRM, или что они все были отклонены.
- Дата создания исходного CRM-лида не является датой новой отправки формы Meta.
- UTM Google и платная Meta-форма могут сосуществовать. Доступных данных недостаточно для молчаливой замены первого источника.
- В октябрьской когорте 730 CRM-записей с подтверждённой платной формой и 730 уникальных FB lead ID. 729 имеют основной источник Meta Ads, одна — Google Ads. Ещё три Meta Ads не имеют FB lead ID.
- Во всей истории 1986 записей с подтверждённой платной формой, 1975 уникальных ID, 11 повторных связей. Два потенциально ошибочно разделяемых между контактами ID затрагивают 13 CRM-карточек.

## Исправления в отчёте

CRM-модель сохраняет FB lead ID, FB form ID, ad ID и organic-флаг. При объединении истории
все разные ID заявок сохраняются; конфликтующие organic-флаги остаются неизвестными.
Основные источники, даты когорт и правила удаления дублей не изменены.

В Channels & Services добавлен CRM-only блок сверки Meta: текущая когорта против всей истории,
уникальные ID заявок, повторные связи, иной основной источник и потенциальные коллизии контактов.
Детализация открывает карточки и исходные ID; CSV также сохраняет Meta-метаданные.
Facebook-файл не является рабочим источником и не нужен для последующих загрузок.

Для полной сверки интеграция должна сохранять ID и время каждой отправки формы, включая повторные
обращения существующих контактов. CRM-экспорт должен включать все этапы, все воронки и всю историю.
